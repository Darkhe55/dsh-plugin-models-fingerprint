它到底在看什么

每条助手消息会生成一个“观测”，指纹由以下不包含声称模型名的字段组成：

  • 协议层：wire API、适配器类型/版本、wire provider、响应 ID 的形状（长度/字母表/前缀）、是否有 replay 元数据。
  • 行为层：输出 token / 字符比（tokenizer 特征）、流式分块粒度、工具参数 JSON 的空格与转义风格、推理内容占比、首 token 延迟与分块间隔（仅用于基线偏离，不参与指纹哈希）。
  • 辅助证据：工具调用 ID 的形状、usage 字段集合、stop reason；这些展示在详情中，但不会单独把同一协议拆碎。

能回答什么

  • 同一声称模型的历史响应，协议指纹是否稳定；何时换了指纹。
  • 两个不同的声称名称是否共享同一指纹（可能是别名、网关重命名或同一上游）。
  • 本次行为统计是否显著偏离该指纹的历史基线；某路由是否长期存在多个指纹。
  • 你可以给指纹写“人工标签”，之后名称与标签不一致会被标出。

不能回答什么

黑盒 API 无法被“证明”为某个具体模型。指纹是证据，不是密码学身份；同一模型经过不同网关可能得到不同协议指纹，不同模型也可能共享相同的 API 外壳。置信度表示证据强度，不是“这是某模型的概率”。最终判断应结合供应商账单、接口文档、人工抽检和这里的标签。

数据与隐私

只保存指标、哈希和 ID 形状，不保存提示词或回复正文。状态文件位于 ~/.dsh/model-fingerprint/state.json.zst，只在本地读取 DSH 会话日志。历史扫描是增量的，日志追加时只解析新帧。

指纹是观测证据，不是模型身份证明。建议给确认过的指纹写人工标签，再让系统对照名称与标签。
